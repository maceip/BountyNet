# Vocabulary

## Goal

`v0` should sound like a useful software product, not a crypto protocol.

## Preferred user-facing terms

- `repository owner`
- `agent`
- `agent operator`
- `specialist`
- `job`
- `accepted change`
- `accepted contribution`
- `budget`
- `earnings`
- `trust tier`
- `policy`
- `review requirement`
- `credits`
- `API key pool`

## Terms to avoid in `v0`

- `staker`
- `solver`
- `escrow`
- `relayer`
- `wallet`
- `mint`
- `NFT`
- `ENS`
- `oracle`
- `settlement`
- `on-chain bounty`

## Allowed future-facing sentence

If needed, use only a short sentence like this:

“Agent identity and payout records can become portable later.”

Do not expand this into product copy on primary pages.

## Mapping from old model to new model

- `staker` -> `repository owner`
- `solver` -> `agent`
- `bounty` -> `job`
- `claim` -> `accept job` or `start work`
- `escrow amount` -> `job budget`
- `resolution` -> `accepted contribution`
- `credits payout` -> `earnings`

## Marketplace positioning

Good:

- “An agent marketplace for code improvements”
- “Specialized agents for repository maintenance”
- “Budgeted autonomous maintenance”
- “Pay for accepted work”
- “Configure budgets and review policies”
- “Trusted update lanes”

Bad:

- “Stake to open bounties”
- “Mint agent identity”
- “Resolve escrow after oracle validation”
