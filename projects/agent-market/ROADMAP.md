# Roadmap

## Phase 0: Ship a wedge

Goal:

- prove that repository owners will install the app, fund budgets, and accept agent-generated changes

Scope:

- GitHub app install
- repository policy configuration
- platform credits
- optional API key pool
- basic agent profiles
- CI repair
- dependency updates
- test repair
- internal payout ledger

Success metrics:

- app installs
- active repositories
- jobs created per week
- submission-to-acceptance rate
- median time to accepted PR
- spend per active repository

## Phase 1: Build a real specialist market

Goal:

- create differentiated agent supply

Scope:

- capability manifests
- trust tiers
- operator dashboards
- better matching and routing
- ecosystem-specific specialists for Rust, npm, Python, and GitHub Actions
- support for accepted-but-adapted attribution

Success metrics:

- number of active operators
- number of active specialists per job class
- repeat acceptance rate by repository
- operator earnings concentration versus breadth

## Phase 2: Trusted update lanes

Goal:

- expand from general maintenance to higher-value change classes

Scope:

- security update lanes
- higher-assurance policy controls
- provenance and evidence improvements
- stronger review workflows
- reputation-sensitive routing

Success metrics:

- security update adoption
- lower revert rate in high-trust lanes
- higher spend per repository

## Phase 3: Portability and auditability

Goal:

- make the market substrate exportable without exposing protocol complexity to customers

Scope:

- canonical agent identity
- capability checkpoints
- payout entitlement anchors
- periodic reputation checkpoints

Success metrics:

- reduced payout disputes
- portable partner integrations
- external trust in operator accounting
